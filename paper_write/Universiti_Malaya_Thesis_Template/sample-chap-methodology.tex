\chapter{RESEARCH DESIGN AND METHODOLOGY}
\label{chap:methodology}

This chapter describes the research design used to implement and evaluate the proposed Nano-Mamba U-Net. The methodology is written to make the experiment reproducible: it specifies the dataset boundary, data discovery procedure, patient-level split, preprocessing pipeline, model architecture, loss function, checkpoint selection, evaluation metrics, and computational profiling. The chapter also distinguishes clearly between methods adopted from prior work and components implemented in this project.

\section{Overall Research Workflow}
The study follows an experimental computing workflow. First, the ACDC cardiac MRI data are discovered and paired with corresponding segmentation labels. Second, patients are separated into training and validation groups using a deterministic patient-level split. Third, all models are trained under the same preprocessing, optimization, and validation protocol. Finally, the best checkpoint for each model is selected by validation mean Dice and evaluated on the held-out validation patients.

\section{Dataset and Data Discovery}
The experiment uses the Automated Cardiac Diagnosis Challenge (ACDC) dataset \cite{bernard2018deep}. The task is multi-class segmentation of three anatomical structures: RV, MYO, and LV. The final experiment discovered 200 valid image-label pairs from 100 patients. Each patient contributes labelled end-diastolic and end-systolic frames, giving two labelled 3D cases per patient.

A practical issue in this project is that the local dataset layout contains paths ending in \texttt{.nii} that may act as containers rather than directly readable NIfTI files. Therefore, the final data discovery procedure checks whether each candidate path is a valid non-empty file or a directory containing the actual NIfTI file. Empty placeholders are skipped. This step is important because directly passing an empty placeholder file to a NIfTI reader causes a loading error. The final data discovery report confirmed 200 valid image-label pairs and no skipped invalid containers.

\section{Patient-Level Training and Validation Split}
The split was performed at patient level rather than case level. This means all labelled frames from the same patient belong either to training or to validation, never both. This design prevents leakage of patient-specific anatomy into the validation set. With random seed 42 and an 80/20 split, the experiment used 80 training patients and 20 validation patients, corresponding to 160 training cases and 40 validation cases.

Let $\mathcal{P}$ denote the set of all patient identifiers. The split can be expressed as:
\begin{equation}
    \mathcal{P}_{train} \cap \mathcal{P}_{val} = \varnothing, \qquad \mathcal{P}_{train} \cup \mathcal{P}_{val} = \mathcal{P}.
\end{equation}
This condition is the core methodological safeguard of the experiment. It ensures that the validation Dice measures performance on unseen patients rather than on additional frames from patients used during training.

\section{Preprocessing Pipeline}
All models use the same preprocessing pipeline implemented with MONAI \cite{cardoso2022monai}. Each image and label pair is loaded from NIfTI format, converted to channel-first representation, resized to a fixed spatial size of $256\times256\times16$, intensity-scaled, and converted to a PyTorch tensor. Applying the same preprocessing to all models is necessary because otherwise observed performance differences could be caused by data handling rather than architecture.

For continuous MRI intensity volumes, trilinear interpolation is used during resizing. If $V(x,y,z)$ denotes the interpolated intensity at a continuous coordinate, the interpolation can be described as a weighted combination of its eight neighbouring voxels:
\begin{equation}
    V(x,y,z) \approx \sum_{i=0}^{1}\sum_{j=0}^{1}\sum_{k=0}^{1} w_{ijk}V_{ijk}.
\end{equation}
Here, $V_{ijk}$ are neighbouring voxel intensities and $w_{ijk}$ are interpolation weights determined by the relative distance between the target coordinate and the neighbouring grid points. For segmentation labels, nearest-neighbour interpolation is used instead, because labels are categorical class identifiers rather than continuous intensity values.

MRI intensity values are relative and scanner-dependent rather than standardized physical units \cite{nyul1999on}. Therefore, intensity scaling is applied before network input. A simple min-max formulation is:
\begin{equation}
    S(I_{xyz}) = \frac{I_{xyz}-\min(I)}{\max(I)-\min(I)+\epsilon}.
\end{equation}
The constant $\epsilon$ prevents division by zero. In practice, MONAI handles these operations in the transform pipeline. The mathematical expression is included to clarify why intensity normalization is needed for stable neural network training.

\section{Nano-Mamba U-Net Architecture}
The proposed model follows a 3D U-Net-style encoder-decoder structure. The encoder uses convolutional blocks and pooling to reduce spatial resolution while increasing feature channels. The decoder uses transposed convolutions and skip connections to recover spatial resolution and preserve boundary information. The architectural modification studied in this thesis is the insertion of a lightweight Mamba-inspired bottleneck at the compressed latent representation.

Each convolutional block consists of two 3D convolutional layers followed by batch normalization and ReLU activation. A convolutional layer transforms a local neighbourhood into an output feature using learned kernels. For a 3D convolution, this can be written as:
\begin{equation}
    Y_{c_o}(p)=\sum_{c_i}\sum_{q\in\mathcal{K}}W_{c_o,c_i}(q)X_{c_i}(p+q)+b_{c_o}.
\end{equation}
Here, $X$ is the input feature map, $Y$ is the output feature map, $\mathcal{K}$ is the local 3D kernel support, and $W$ and $b$ are trainable parameters. This equation also shows the locality of convolution: each output voxel depends on a neighbourhood around position $p$.

Batch normalization stabilizes training by normalizing intermediate features within a mini-batch \cite{ioffe2015batch}. For a feature value $x$, batch normalization can be expressed as:
\begin{equation}
    \hat{x}=\frac{x-\mu_{\mathcal{B}}}{\sqrt{\sigma_{\mathcal{B}}^2+\epsilon}}, \qquad y=\gamma\hat{x}+\beta.
\end{equation}
The parameters $\gamma$ and $\beta$ are learned, allowing the network to recover suitable feature scales after normalization. ReLU activation is then applied as:
\begin{equation}
    f(x)=\max(0,x).
\end{equation}
These components are standard neural network operations and are not claimed as novel contributions of this thesis.

\section{Mamba-Inspired Bottleneck Implementation}
The bottleneck receives a compressed 3D feature map. Let this tensor be:
\begin{equation}
    \mathcal{X}\in\mathbb{R}^{B\times C\times H\times W\times D}.
\end{equation}
The tensor is serialized across the spatial dimensions to obtain a sequence:
\begin{equation}
    \mathbf{X}_{seq}=\mathrm{reshape}(\mathcal{X})\in\mathbb{R}^{B\times L\times C}, \qquad L=HWD.
\end{equation}
This operation does not create new anatomical information. It changes the representation so that the bottleneck can process compressed volumetric features as a sequence.

The implemented bottleneck is Mamba-inspired rather than a full selective scan implementation. It uses linear projection, depthwise one-dimensional convolution, gating, output projection, and residual addition. A simplified representation of the operation is:
\begin{equation}
    Z = \mathrm{Proj}_{out}\left(\mathrm{Gate}\left(\mathrm{DWConv1D}\left(\mathrm{Proj}_{in}(\mathbf{X}_{seq})\right)\right)\right)+\mathbf{X}_{seq}.
\end{equation}
Here, $\mathrm{Proj}_{in}$ and $\mathrm{Proj}_{out}$ are learned linear projections, $\mathrm{DWConv1D}$ is a depthwise sequence convolution, and $\mathrm{Gate}$ denotes a learned nonlinear gating operation. The output is reshaped back into 3D feature form before being passed to the decoder.

This design choice must be interpreted carefully. The original Mamba paper proposes selective state space sequence modeling \cite{gu2023mamba}. The implementation in this project uses a lightweight PyTorch block inspired by this direction, but it does not claim to reproduce the full hardware-aware selective scan. The research contribution is therefore the integration and evaluation of a compact sequence-inspired bottleneck inside a cardiac MRI segmentation model.

\section{Comparison Models and Ablation Design}
The experiment compares Nano-Mamba U-Net with several reference architectures. The 3D U-Net baseline represents the standard encoder-decoder approach. Attention U-Net represents attention-gated skip connections. SegResNet16 represents a residual convolutional segmentation model. Two ablation variants are included to study the role of the bottleneck: No-Mamba U-Net replaces the Mamba-inspired bottleneck with convolutional blocks, while Half-Mamba U-Net reduces the bottleneck capacity.

The purpose of the ablation study is not to prove that every Mamba-inspired configuration must outperform every convolutional configuration. Instead, the ablation tests whether the proposed bottleneck improves the accuracy-efficiency trade-off under the same training and validation protocol. This distinction is important because the final results show that No-Mamba U-Net slightly outperformed Nano-Mamba U-Net in mean Dice, while Nano-Mamba U-Net retained the lowest parameter count.

\section{Training Objective and Optimization}
The models are trained using a Dice-Cross Entropy objective. Dice loss addresses region-level overlap, while cross entropy provides voxel-wise class supervision. For class $c$, the Dice score is:
\begin{equation}
    \mathrm{DSC}_c=\frac{2\sum_i p_{i,c}g_{i,c}}{\sum_i p_{i,c}+\sum_i g_{i,c}+\epsilon}.
\end{equation}
The corresponding Dice loss can be written as:
\begin{equation}
    \mathcal{L}_{Dice}=1-\frac{1}{C}\sum_{c=1}^{C}\mathrm{DSC}_c.
\end{equation}
The multi-class cross-entropy term is:
\begin{equation}
    \mathcal{L}_{CE}=-\sum_i\sum_c g_{i,c}\log(p_{i,c}).
\end{equation}
The total loss used for optimization is:
\begin{equation}
    \mathcal{L}_{total}=\mathcal{L}_{Dice}+\mathcal{L}_{CE}.
\end{equation}
Here, $p_{i,c}$ denotes the predicted probability for voxel $i$ and class $c$, while $g_{i,c}$ denotes the one-hot ground-truth label. This loss is a standard practical choice for medical segmentation and is implemented using MONAI's Dice-Cross Entropy loss.

Optimization is performed with AdamW \cite{loshchilov2017decoupled}. The learning rate is $1\times10^{-4}$ and weight decay is $1\times10^{-5}$. All models are trained for 150 epochs. The batch size is set according to model memory requirements: lighter models use batch size 2, while heavier models use batch size 1. These settings are kept consistent in the final experimental script to support fair comparison.

\section{Checkpoint Selection and Evaluation Metrics}
A key methodological correction in the final experiment is validation-based checkpoint selection. Earlier exploratory scripts saved best models according to training loss, which is not a reliable indicator of generalization. In the final experiment, the checkpoint is saved only when validation mean Dice improves. If $\overline{D}^{(e)}_{val}$ denotes the validation mean Dice at epoch $e$, the selected checkpoint is:
\begin{equation}
    e^*=\arg\max_e \overline{D}^{(e)}_{val}.
\end{equation}
The final reported metrics are computed from this selected checkpoint on the held-out validation cases.

The primary reported segmentation metric is mean Dice across RV, MYO, and LV:
\begin{equation}
    \overline{D}=\frac{D_{RV}+D_{MYO}+D_{LV}}{3}.
\end{equation}
The study also reports parameter count and inference speed. Parameter count measures the number of trainable parameters in the model, while inference speed is measured as frames per second on the same hardware environment. These computational metrics are necessary because the research question concerns the trade-off between accuracy and lightweight design, not Dice score alone.

\section{Hardware and Reproducibility}
All experiments are run using PyTorch and MONAI on a single NVIDIA RTX 4060 GPU with 8GB VRAM. The random seed is fixed to 42 for Python, NumPy, and PyTorch. CuDNN deterministic settings are enabled to improve reproducibility. The final experiment script saves the patient split, per-case validation scores, training logs, checkpoints, and summary CSV/JSON files. These outputs provide an auditable evidence chain linking the reported thesis tables to the executed code.

\section{Methodological Summary}
The methodology is designed to support a fair and cautious evaluation. The proposed Nano-Mamba U-Net is compared with several baseline and ablation models under the same patient-level split and preprocessing pipeline. The model is not evaluated using training-set performance, and it is not claimed to be a full implementation of the original Mamba selective scan. Instead, the experiment tests whether a compact Mamba-inspired bottleneck can provide competitive cardiac MRI segmentation performance with a low parameter count.
